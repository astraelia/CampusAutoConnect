# 校园 Wi-Fi 连接助手使用手册

版本：1.0.1。适用 Windows 10/11 x64。内置帮助与随包手册使用同一份内容。
理论上，完成对应精确网络档案、认证入口、安全凭据和自动许可配置后，可用于北京工业大学本部兼容已适配认证流程的校园网。中蓝公寓宿舍内校园网已实测能够自动连接；本部其他区域及其他校区有待验证，1.0.1完整启动性能和换机效果须分别测试。

仓库和发布包不带账号密码或校园网络参数，网络档案默认空、自动认证默认关闭、登录任务默认未安装。新电脑需本人重新配置；同一Windows用户升级会复用原有本机存储，不表示下载包携带私人数据。“自动连接”指Windows已连Wi-Fi后由软件认证，不代替Windows选网或切网。

## 01 · 安装、升级与首次打开

1. 将 ZIP 全部解压到本人可写的固定目录，例如 D:\Apps\CampusAutoConnect。不要在压缩包预览中运行。
2. 保留 CampusAutoConnect.exe、CampusAutoConnect-CLI.exe、_internal 以及文档的相对位置。无需安装 Python；网页抓包需要本机已有 Edge 或 Chrome。
3. 升级前在旧版点击“退出程序”，等待托盘和后台退出，再启动新版并确认版本 v1.0.1。保留旧版完整目录供回退。
4. 初次没有网络档案时自动显示本教程。左侧目录可选择章节，顶部可以搜索，底部“上一步/下一步”按顺序阅读。
5. 报告保存在当前 EXE 所在目录的 reports 中。若放在不可写的 Program Files 等目录，报告会明确保存失败；请移动完整程序包到可写固定目录，不会静默改存其他位置。

预期：主窗口正常显示，中文可读。首次配置和开发测试均不会替你开启自动认证或登录启动。
异常：缺少 _internal 或启动失败时重新完整解压；仍失败可用同目录 CLI 的 --self-check runtime 检查运行环境。启动辅助监测仅覆盖其已启动后主进程的退出，不承诺覆盖所有装载前故障。

下一步：[打开连接概览](page:overview)，阅读网络检测说明。

## 02 · 检测当前网络

1. 先使用 Windows 连接校园 Wi-Fi；本软件不负责选网、断网或重连。
2. 在“连接概览”点击“检测网络”。网络和系统查询在工作线程执行；可以切换页面，必要时点击“取消本次操作”。
3. 查看状态、原因、执行步骤和最近检测时间。系统查询或 DNS 可能较慢，取消仍需等待已经发出的有界调用结束。

预期：“互联网可用 / already_authenticated”表示独立探测通过，本次没有重复登录；这不能验证新输入的账号密码，也不证明是本软件完成的认证。
“需要认证”表示存在档案允许的入口，真实登录前还要检查路由、页面和实时协议。
异常：untrusted_network 时核对精确 SSID 和唯一启用档案；无网络、SSID 权限或网络变化时先排查 Windows 连接。

下一步：[打开网络档案](page:profiles)。已有连接正常的档案无需为抓包而重建。

## 03 · 配置网络档案与认证入口

1. 在连接概览点击“配置当前网络…”，或在网络档案中添加、选择并编辑档案。
2. 名称可自行命名；SSID 必须与实际网络精确一致，包括大小写，不能只凭名称包含 BJUT 授予信任。
3. 填写本人已核对的认证页和认证服务源地址。可以点击“从脱敏抓包填写认证地址…”选择旧版或新版 PortalCapture JSON，再核对填写结果。
4. HTTP 入口只有主动勾选“允许本档案使用 HTTP 认证”才可用。HTTP 会未加密传输账号密码；HTTPS 证书验证始终开启，不自动降级。
5. 全零 MAC 兼容仅在页面实际返回全零且本人明确允许时使用。VLAN=0 按页面原值支持，无需改成其他数字。
6. 首次保留档案自动认证关闭，保存后重新检测并先手动测试。

修改 SSID 或认证目标会撤销相关兼容许可及档案自动勾选，需要重新核对。解析抓包、发现网页或页面跳转本身不授予信任。
凭据引用默认 shared；多个档案使用相同引用会共享同一账户。删除档案不删除安全凭据。
导入档案生成新 ID/凭据引用，全部停用并清除敏感许可；导出包含 SSID 和目标地址，请私下保管，不能当脱敏报告分享。

下一步：[打开安全凭据](page:credentials)。

## 04 · 保存账号密码并确认成功

1. 先选择对应档案，确认“安全凭据”页面的凭据引用与档案一致。默认 shared 可以共享；独立引用对应另一份记录。
2. 输入纯账号，或只带一次与学校实时配置一致后缀的完整账号。输入新密码，点击“保存 / 更新凭据”。
3. 等待异步保存与回读核对。出现“已保存并复核”才表示写入内容与本次输入一致。密码输入框在提交后清空。
4. 退出再打开时，输入框为空属于正常行为。页面显示上次确认记录及时间，并注明本次尚未重新检查；点击“检查是否已保存”可确认当前 Windows 记录。
5. 修改已有凭据时重新填写账号和新密码后保存；空输入不会覆盖或删除已有记录。删除需要点击“删除凭据”并确认，会影响所有共享该引用的档案。

存储状态与输入草稿分别显示：正在输入的新内容尚未保存，不会改变上一份已存记录。切换引用会清除输入内容，防止写入错误引用。
“已找到凭据”仅表示记录可读取；“已保存并复核”仅确认存储一致，均不代表学校接受该账号密码。
“查询失败”不等于未保存。“写入调用已完成但复核失败”表示结果待确认，请主动检查，勿直接判定密码丢失。
上次确认记录只是历史信息。外部在 Windows 凭据管理器删除记录后，只有本次主动检查才能发现当前已不存在。

账号密码只保存在 Windows Credential Manager，程序显式使用 WinVaultKeyring，失败不会回退到文件。已保存的账号密码不回填界面，不进入报告。
开发自检仅使用独立随机命名空间的虚构凭据，不访问你现有的正式记录。

下一步：[回到连接概览](page:overview)进行一次手动测试。

## 05 · 手动认证与结果判断

1. 当前校园 Wi-Fi 稳定、精确档案和凭据已准备好后，点击一次“手动测试认证”。一次操作最多提交一次，不自动重试。
2. 不要同时在另一个网页登录；并发操作会返回 busy。可以取消，网络或档案变化也会阻止后续提交。
3. 查看三个不同事实：是否尝试发起请求、服务器是否接受、独立互联网验证是否通过。

预期：服务器接受且独立联网验证通过后显示“互联网可用”。如果原本已联网，本次会跳过登录，不能验证输入密码。
失败时会定位到诊断页；根据错误码检查具体环节。不要为了制造待认证状态而在远程使用期间强制断网或退出校园网。
错误密码、验证码和设备限制的真实响应尚未逐项确认。服务端拒绝时按 manual_action 处理，不猜测远端错误，不循环尝试。

下一步：手动连接成功后再决定是否启用自动功能，或[打开诊断与监测](page:logs)。

## 06 · 自动认证、后台与登录启动

以下条件彼此独立：档案启用且允许自动认证、全局允许自动认证、后台正在运行。只开启一个开关不会自动登录。

1. 先完成手动测试，再在网络档案启用该精确 SSID 的自动认证。
2. 打开“后台与启动”，勾选全局许可后点击“保存并启动后台”；“仅保存开关”不会启动后台。
3. 查看后台状态。STOPPED 表示不会自动认证；DISABLED 表示后台存在但全局关闭；BLOCKED 表示某项故障阻止继续自动尝试。
4. 确认固定程序目录后，勾选“登录 Windows 后自动启动到托盘”。登录后立即启动托盘并确认后台，网络就绪及稳定后才认证；托盘不可用显示窗口。它不替你开启全局许可。
5. 升级或移动目录后主动刷新；如果是旧任务，展开高级操作，点击“修复旧版登录启动到当前版本”。修复保留原启用状态，不立即运行任务；归属不明不覆盖。1.0.1 同时移除旧任务固定延迟，未修复仍运行旧版。
6. 登录任务最近运行时间、结果和后台状态分别显示。任务正在运行、进程正常退出均不能单独证明校园网已认证。已有后台不会因登录入口被重启，故障阻塞和次数保留。

1.0.1 优先使用 Windows 原生查询，只有技术性故障才受控回退 PowerShell；网络未就绪、路由不确定和不可信网络不会因回退获得认证许可。脱敏诊断的 network_query 为当前前台进程，实际后台查询方式见 automation.monitor.network_query；日志 startup/timing 记录时间点和耗时。

换电脑须完整复制程序目录，在新电脑重新保存 Windows 安全凭据并复核网络档案和自动许可。正式包面向 Windows 10/11 x64；其他系统架构和未实测环境单独标记。

明确临时故障最多初次加两次重试，间隔 5 秒、15 秒。账号、验证码、协议、信任、TLS 等故障停止自动尝试，重连和唤醒不清除当前进程阻塞。
网页抓包持有认证互斥期间，新认证会被拒绝为 busy，已有请求先等待结束；不通过重启后台清除次数或阻塞。
Windows 登录自启动、真实切网、睡眠唤醒、其他区域和 Win10 需本人分别测试。当前连接正常不代表这些项目都已验收。

[打开后台与启动](page:automation)。

## 07 · 托盘、主题、取消与完整退出

“外观设置”可选择跟随系统、浅色或深色，点击保存后生效。关闭方式也在这里保存。
勾选关闭收起且托盘可用时，右上角关闭会隐藏到托盘。图标可能位于任务栏 ^ 中；双击或右键打开主窗口即可恢复。
点击“退出程序”会取消操作、停止并等待后台结束，再完整退出。后台有系统调用未结束时会等待；失败时保留窗口供重试，不强杀正在认证的进程。
一次退出不会删除用户已启用的登录任务；需要撤销时，在后台与启动关闭登录启动。
抓包时点击“停止抓包并保存”正常结束；完整退出也会请求停止并等待浏览器工作结束。勿直接用任务管理器强杀来代替保存。

[打开外观设置](page:settings)。

## 08 · 诊断监测与深入检查

1. 打开“诊断与监测”，点击“开始监测”检查报告目录。
2. 在连接概览按需检测或手动认证。诊断页实时显示本进程实际阶段和脱敏请求摘要。
3. 点击“独立分步复查”进行另一次无凭据检查：运行环境、精确档案、探测点、目标、路由、TLS、后台及启动状态。
4. 需要复查页面会话、MAC/VLAN 和实时配置时，点击“深入诊断（不登录）”。它使用生产门槛和解析器，前置条件失败就停止，不读取凭据、不登录。
5. 点击“结束监测并保存”，再打开报告目录，或复制脱敏监测报告。

报告分清证据来源：主程序实际记录属于对应操作；独立复查属于另一次检查；共享后台事件不能按时间相近就归因于某次点击。
未执行不等于通过。凭据读取尝试不证明存在记录，请求尝试不证明服务器收到，成功响应不代替独立联网验证。
保存档案后，上次操作诊断不会被追溯修改，应重新检测。深入诊断显示自己的时间和结果，不冒充上次认证内部步骤。
日常检测/认证默认只更新界面内存诊断和已有滚动日志，不生成完整报告。开始监测后才随操作保存；独立复查、深入诊断和主动保存也会生成报告。保存失败不改变连接结果。

[打开诊断与监测](page:logs)。

## 09 · 网页抓包、自动跳转与分析

1. 打开“抓包与分析”，点击“开始抓包并自动打开认证页”。先等待在途认证结束，随后专用 Edge/Chrome 自动打开已配置页面；无有效入口时访问 HTTP 探测页发现跳转。
2. 确认显示的是学校官方页面。发现页面不等于授予主程序认证信任；程序不会自动填写账号密码或点击网页登录。
3. 只在这次打开的专用浏览器中操作。普通浏览器、Windows 自动弹出的其他窗口和主程序 HTTP 请求不属于这个浏览器抓包范围。
4. 页面没有打开时可点“重新打开认证页”，也可在专用浏览器手动输入本人已确认的入口。工具不会切网或修改系统代理、路由、证书。
5. 完成后点“停止抓包并保存”。自动显示分析结果：请求数、失败数、是否捕获登录及服务端成功摘要。也可以选择已有 1.1.0/1.2.0 脱敏 JSON 分析。

最多保留 600 条相关请求，达到上限会标记截断；没有请求时明确显示空记录。浏览器缺失、启动失败或结果保存失败不会显示成成功。
2 条局部请求失败可以与后续登录成功摘要同时存在，应查看发生环节及最终独立联网结果。
本地抓包保留主机、端口和受限路径供填写档案；账号、密码、Cookie、Token、原始请求和完整响应正文不保存。主机信息仍属本机网络信息，原文件请私下保管。
认证网页使用现有专用 Edge/Chrome，抓包控制与分析已进入主程序；网页本身不嵌入 Qt 窗口。

[打开抓包与分析](page:capture)。

## 10 · 报告位置、隐私与保存失败

报告固定在当前 EXE 实际所在目录的 reports\日期_时间_会话编号，不受快捷方式工作目录或后台启动方式影响。
diagnostic.json / diagnostic.txt 是脱敏诊断；PortalCapture_session.json / .txt 是网页抓包及分析。session.json 和 active.lock 是管理元数据及活动锁，不能用文件存在判断进程活动。
生命周期仅保留 reports/lifecycle-latest.json，不为每次启动新建报告会话。观察器只覆盖成功附着后的进程退出；requested 不等于观察成功。
“打开报告目录”打开当前已生成会话；主动诊断的新会话独立保存。日常连接不会因此不断增加目录。
“外观设置 → 报告保存与自动清理”默认保留 7 天、最多 20 组、50 MiB。程序启动及持续运行每 24 小时检查，关闭期间在下次启动补检查，不额外安装系统清理任务。
清理上限适用于可清理报告，活动、保留标记和默认排除的抓包会话除外。勾选“保留当前报告”可长期保留；只有本人明确勾选并保存“同时清理网页抓包原件”才将抓包纳入。
旧版报告没有管理标记，自动清理先跳过。点击“预览并清理过期报告…”查看数量与容量，确认后将旧报告纳入管理，并只删除本次确认且仍符合规则的候选。取消不执行删除。
报告被占用、路径有链接/联接或有未知文件时跳过/报错；最近结果会显示删除及失败数量，可处理后主动重试，不影响认证。
诊断隐藏 SSID、IP、主机、档案 ID、账号、Cookie、Token 和响应体；复制脱敏监测报告不会复制本地抓包的目标值。
目录不可写、磁盘满或文件占用时明确显示保存失败；不会悄悄换位置，窗口结果仍可复制。需要时移动完整程序到可写固定目录后重试。
运行配置和日志仍在 %LOCALAPPDATA%\CampusAutoConnect，凭据仍在 Windows Credential Manager；这与 reports 位置不同。
更新前备份本人需要的报告，不把旧 reports、真实配置或抓包放进开发仓库或重新打包分发。

## 11 · 常见故障与下一步

| 状态或错误码 | 处理方法 |
| --- | --- |
| untrusted_network | 检查当前 SSID、档案启用状态和是否有重复匹配；不模糊匹配 |
| untrusted_target | 核对认证页、API 源地址、精确端口及 HTTP 许可，不自行扩大信任 |
| protocol_unverified / protocol_changed | 入口未配置或实时分支变化，做无凭据深入诊断，必要时网页对照抓包 |
| session_fields_invalid / session_ip_mismatch | 页面会话字段不完整或与本机 Wi-Fi 不一致，等待网络稳定后复查 |
| session_mac_invalid / zero_mac_permission_required | 区分格式错误与全零许可；仅允许页面实际全零，不伪造字段 |
| session_vlan_invalid | VLAN 格式或范围不支持；VLAN=0 已兼容，不擅自替换 |
| route_unconfirmed | 检查校园 Wi-Fi、VPN/TUN、活动虚拟网关和目标路径；不关闭安全门槛强行提交 |
| tls_error | 证书验证失败，不关闭验证或自动降级；核对学校认可的入口 |
| credentials_missing | 核对档案引用，再主动检查保存状态，必要时重新保存 |
| credential_store / credential_verify | Windows 存储操作失败或写后复核失败；查看状态区别并主动复查，不发送密码 |
| manual_action | 后缀冲突、服务端拒绝、验证码或设备限制等需人工检查；不要无限重试 |
| busy | 另一个检测、认证、凭据更新或网页抓包占用互斥，等待完成 |
| startup_error | 查询任务状态，区分旧路径与归属冲突；未知任务不覆盖 |
| report_save_failed | 检查安装目录写权限、磁盘和文件占用，复制窗口脱敏结果 |

只做与当前问题相关的检查，不反复点击登录。当前互联网可用时，正常检测会跳过登录。

## 12 · 反馈、回退与卸载

反馈请附版本、操作步骤、预期与实际结果、发生时间及脱敏诊断。不要发送真实配置、账号密码、Cookie、Token、完整 HAR 或带凭据截图。
开发验证、Windows 本机检查、真实校园网连接、自启动和不同区域测试分别记录通过/失败/未测，不互相替代。
回退：完整退出新版及后台，使用保留的旧版完整目录；不要同时运行两个版本。已有登录任务指向哪个版本需要主动刷新核对，开发不会替你修改正式任务。
卸载：先关闭全局自动认证、停止后台，主动关闭登录启动，再完整退出。按本人需要保留报告和配置；删除安全凭据需要在凭据页主动执行。
CLI 高级入口为 CampusAutoConnect-CLI.exe --help。--self-check runtime/gui/background/credentials/startup 使用隔离检查；startup-ui 通过真实 --startup 分发入口验证隔离目录中的桌面/后台启动和退出，全局认证保持关闭。--self-check browser 访问本机模拟 Portal，只发送虚构数据；这些结果不能当真实校园网验收。
