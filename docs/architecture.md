# 架构与模块职责

当前版本1.0.1，Python3.12+、Windows10/11 x64。GUI和CLI共用同一服务层；核心逻辑不依赖PySide6。

| 层 | 职责 |
| --- | --- |
| core | 不可变模型、状态机、精确档案规则、Portal信任、Windows网络/路由查询 |
| infrastructure | 严格JSON、用户目录、跨进程锁、原子文件、脱敏日志、系统事件/启动和报告管理 |
| security | 显式WinVaultKeyring；安全凭据读写、写后核对，拒绝文件回退 |
| adapters | 已核对ePortal页面/配置/JSONP解析和受限单次登录分支 |
| services | 一次认证、后台调度、应用组合根、诊断、抓包及报告编排 |
| ui / cli | 调用服务；GUI用工作线程处理网络、存储和任务操作，只在主线程更新控件 |

## 一次认证

无凭据独立探测 → 精确启用档案 → 可信入口及路由 → 无凭据页面/实时配置prepare → 再次网络/档案/授权核对 → 读取对应安全凭据 → 提交前复核网络、路由、取消和授权 → 最多一次提交 → 独立互联网验证。

已联网跳过登录；未知网络、协议、信任或上下文失败在读凭据/提交前停止。一份准备上下文只能消费一次。服务端接受不等于互联网可用，请求尝试不等于送达。

## 网络与后台

Native WLAN读取原始精确SSID，原生IP Helper读取地址/物理属性/实际目标路由。只在识别的技术故障回退批量PowerShell，当前进程记住降级；拒绝/未就绪/不可信结果不因回退获得许可。关键时点实时查询，不用旧缓存替代。

自动调度要求全局及精确档案许可、网络就绪和稳定；一个工作线程，事件/电源变化立即取消旧代次，排空前不启动新任务。明确临时故障总计最多三次，凭据/协议/TLS/信任等锁止，重连和唤醒不清除进程内阻塞。

GUI、后台和认证分别单例/互斥；凭据修改共用认证锁。登录固定`--startup`创建托盘并复用后台；后台固定`--background`。当前用户最低权限任务须本人主动启用/修复，不立即执行或覆盖未知任务。

## 存储与报告

配置/偏好/日志在LOCALAPPDATA应用目录，默认空档案、自动关闭；账号密码仅在Windows安全凭据。报告在EXE实际目录reports，普通操作默认内存诊断，主动监测/检查/保存才写完整报告。抓包用独立Edge/Chrome并持认证锁，不重启后台。

报告清理只处理受管白名单文件，保护活动/保留/默认抓包，旧报告先确认；拒绝链接/联接和未知内容。取消与退出协作排空，不强杀认证工作。

## 构建与公开分发

PyInstaller生成共享`_internal`的GUI/CLI目录包，隔离DLL搜索环境，验证组件来源，附许可证、BUILD_INFO和SHA256SUMS。构建发现真实配置、报告、日志或抓包时拒绝打包。公开导出使用固定文件清单，不包含原本机Git历史和私人审计资料。
