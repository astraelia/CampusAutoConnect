# 首次配置指南

适用版本：1.0.1，Windows 10/11 x64。仓库和发布包不预填网络档案、认证地址或账号密码；新电脑需要本人配置。同一 Windows 用户下升级会复用本地已有设置。

## 1. 准备环境

完整解压 Windows ZIP 到本人可写的固定目录，保留 `_internal`；通过 Windows 连接自己的校园 Wi-Fi，然后打开软件。首次保持自动认证和登录启动关闭。普通认证无需浏览器，网页抓包需要本机已有 Edge 或 Chrome。

## 2. 建立网络档案

在“连接概览”点“检测网络 → 配置当前网络…”，或在“网络档案”点“添加当前 Wi-Fi / 手动添加”。

| 字段或开关 | 填写与作用 |
| --- | --- |
| 名称 | 自己易识别的显示名称，不授予信任 |
| SSID | 本人实际 Wi-Fi 的精确名称，区分大小写和空格；不凭包含 BJUT 授权 |
| 启用档案 | 核对后才启用；停用档案不参与认证 |
| 适配器 | `bjut`，使用已支持的 ePortal 分支 |
| 认证页地址 | 学校实际提供、本人核对的完整页面地址，不照搬他人参数 |
| 认证服务源地址 | API 的协议、精确主机及端口，不含路径、参数或账号；与认证页同协议、同主机 |
| HTTPS可信主机 | 已核对的精确主机及必要端口，不带路径、通配符或账号；证书验证仍开启 |
| HTTP认证许可 | 默认关闭，仅本人确认实际流程需HTTP时开启；HTTP本身不加密账号密码 |
| 全零MAC兼容 | 默认关闭，仅允许使用页面实际返回的全零值，不补造缺失字段；VLAN=0已按原值兼容 |
| 凭据引用 | 默认 `shared`；相同引用共用一份本机安全凭据，不同账号使用不同引用 |
| 档案自动认证 | 首次关闭；手动连接成功后再开启 |

可从本人已有的脱敏 PortalCapture JSON 将地址填到编辑框，再人工核对、许可和保存。解析抓包、发现网页或页面跳转不自动授予信任；受支持路径、实时配置与端口仍会重新检查。

修改 SSID、认证入口或信任目标后会撤销相关兼容许可及档案自动勾选，需重新确认并先手动测试。

## 3. 保存安全凭据

1. 选择对应档案，在“安全凭据”核对凭据引用。
2. 输入纯账号，或只带一次正确学校后缀的完整账号，以及自己的密码。
3. 点“保存 / 更新凭据”，等待“已保存并复核”；密码框会清空。
4. 重开后点“检查是否已保存”核对当前记录。输入框为空是正常行为；历史确认不代替当前检查。

账号密码只存当前 Windows 用户的 Credential Manager，不写入 JSON、日志、源码或命令行。保存成功不等于学校接受账号密码。换电脑或 Windows 用户后需要重新保存。

## 4. 先手动连接

当前确实待认证时，在“连接概览”点一次“手动测试认证”。单次最多提交一次；并发返回busy，取消、切网或配置变化会阻止后续提交。

- `already_authenticated`：原本已有互联网，本次未登录，不能验证新密码。
- 服务端接受：还需独立联网探测通过，才能报告互联网可用。
- 失败：查看执行阶段和错误码，按[常见问题](FAQ.md)处理，不连续点登录。

## 5. 再开启自动认证与自启动

1. 在该精确档案启用自动认证并保存。
2. 在“后台与启动”勾选全局许可，点“保存并启动后台”。“仅保存开关”不会启动进程。
3. 查看后台状态：STOPPED为未运行，DISABLED为全局关闭，BLOCKED为故障锁止。
4. 固定程序目录后，主动开启“登录 Windows 后自动启动到托盘”。它不替代档案和全局许可。
5. 移动目录或升级后，刷新并在高级操作主动修复本应用旧任务到当前路径；不覆盖未知任务、不立即执行任务。

档案、全局许可、后台及实时门槛同时满足才可自动认证。1.0.1取消固定任务延迟，仍等待网络就绪与稳定，不承诺每台电脑相同耗时。

## 6. 多区域、导入导出与换机

设计上可用于本部兼容认证流程的区域；已实测中蓝公寓宿舍自动连接，本部其他区域和其他校区待验证。每个不同SSID分别配置，同名SSID也仍须核对目标、实时会话和路由。

导出无账号密码，但含网络名称和主机，需私下保管。导入全部停用，自动认证关闭，HTTP/全零MAC许可清除，并生成新凭据引用；重新核对、保存凭据并先手动测试。不要将真实配置、日志、reports或抓包放进公开仓库或重新分发的ZIP。
