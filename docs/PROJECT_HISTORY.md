## 主要失败与处理

| 问题 | 原因与处理 | 当前边界 |
| --- | --- | --- |
| 安装/pytest临时目录失败 | 使用工作区可写TEMP/TMP、模块入口和复制链接方式 | 环境问题单独记录，不删断言 |
| 受限会话CIM/WLAN/本地管道拒绝 | 保留断言，在普通Windows用户环境复核 | 沙箱拒绝不等于产品或校园认证失败 |
| 损坏或深层JSON异常 | 严格结构/容量校验、安全恢复、保留原件 | 备份只供查看，不能自动恢复信任 |
| Windows原子写被读句柄占用 | 每文件I/O锁与跨进程事务 | 外部占用仍明确失败 |
| 取消或切网后仍可能提交 | 读凭据前和提交前复核，代次取消，排空旧工作 | 取消是协作式，不强杀调用 |
| 任务主体或默认权限误判 | 账户/SID规范化，XML与最低权限共同核对 | 未知任务不覆盖 |
| Qt本地socket与线程退出风险 | 显式对象生命周期、wait(0)确认原生线程结束、延迟删除排空 | 一次CRT异常根因未独立证实，长期稳定性另测 |
| 被动刷新覆盖未保存设置 | 保留脏状态，代次过滤迟到结果 | 并发变更仍受互斥控制 |
| Qt打包DLL冲突 | 隔离构建PATH、检查二进制来源 | 不只看PyInstaller返回码，必须实启冻结GUI |
| HTTPS身份不匹配/HTTP流程阻塞 | 不关闭TLS；后续按档案明确许可已观察HTTP分支 | HTTP不加密，证书问题未被“修好” |
| 旧档案缺地址/HTTP许可 | 明确缺项及配置入口 | 发生在读凭据前，不属于密码被拒 |
| 重复账号后缀 | 依实时配置只保留一次精确后缀 | 冲突停止，不猜账号域 |
| 页面全零MAC、VLAN=0不兼容 | 保留原值，VLAN=0受支持，全零MAC需单独许可 | 不伪造字段，不取消IP/路由/协议门槛 |
| 活动虚拟网关触发路由阻塞 | 保留目标路径和风险检查 | VPN/TUN兼容范围仍待对照测试 |
| 凭据保存状态不清楚 | 写后回读，历史收据与当前主动检查分开 | 不回填账号密码，存储成功不等于登录成功 |
| 登录只起隐藏后台、报告累积 | 1.0.0增加托盘入口和后台复用，日常报告减量/受控清理 | 不重启后台清BLOCKED，不盲删旧报告 |
| 浏览器自检清理时仍持报告锁 | 先关闭服务并释放锁，再清临时目录 | 活动保护保留 |
| 保留动作产生空目录 | 保留前保存当前内存诊断 | 已有回归 |
| 启动慢 | 原生查询、批量回退、零固定延迟、并行探测 | 查询毫秒数不能代替完整启动认证计时 |
| 公开分发隐私 | 默认空档案、固定公开清单、运行数据拒绝打包、私人历史不推送 | 本机已有设置仍由本人独立管理 |

## 现场状态与未完成验证

在完成相应配置且认证流程兼容的条件下，设计上可用于北京工业大学本部各区域校园网。**中蓝公寓宿舍内校园网已实测能够自动连接；本部其他区域及其他校区有待验证。** 软件只在Windows已连接Wi-Fi后认证，不负责选网/切网。

尚待独立验证：1.0.1多次完整重启耗时、其他电脑/干净Win10、跨区域、IPv6-only、多网卡和VPN/TUN、学校错误密码/验证码/设备限制响应、真实睡眠/切网、长期驻留、多显示器/DPI，以及观察器自动启动至主GUI异常退出的完整链路。

自动化、模拟服务器、冻结自检、已有互联网与服务端接受均不能单独代替真实校园网和整体验收。未知协议/验证码等失败关闭，不提供绕过能力。
